What we learned

统一边界，而不是统一一切

跨团队复用的重点，是访问、治理与运行方式，而不是强制迁移知识或替换现有工具。

核心认识

Document Knowledge 与 System Knowledge 是平行且互补的能力。

企业知识既存在于 Dify、Git、Confluence、Requirement 和 Design 中， 也存在于 Source Code、Program、Call Graph、Batch Flow、Data Lineage 与 Runtime Evidence 中。

不强制统一

Current gap

当前关键缺口

技术方向足以进入下一阶段验证，但共享服务缺少可持续的生产级 AI 基础。

Production-grade Group AI Capability Approved LLM、Embedding、OCR、Document Understanding 与可规划的 Production Quota。
共享 Service Account 稳定服务身份、凭证生命周期、成本归属、审计、合规与 Production Support。
Business Sponsorship 推动能力从 Ideation / PoC 进入有明确 Owner、用例和运行责任的 Production 路径。

Recommendation

下一阶段怎么推进

不等待全部基础设施统一，通过真实 Use Case 和多个 Provider 逐步验证公共边界。

建议行动

用聚焦验证替代完整平台建设。

  1. 01 明确优先 Use Case 确认业务价值、目标用户、Data/System Owner 与成功标准。
  2. 02 定义最小公共接口 Provider、Identity、Authorization、Evidence、Citation 与 Health。
  3. 03 进行跨 Provider 验证 以 AMH Dify 与 HASE GitHub-based Knowledge Base 为起点。
  4. 04 建立质量与生产标准 覆盖复杂文档、Retrieval、Citation、Permission、Cost 与 Support。

需要管理层支持

本次需要确认方向与生产化条件，而不是最终技术选型。

  1. 01 Business Sponsorship 推动 Group AI Production Access、Service Account、Quota 与合规审批。
  2. 02 认可联邦式方向 复用公共基础能力，不强制一个 Backend、Provider 或 UI。
  3. 03 确认 Owner 与资源 明确 Accountable Owner、Engineering Capacity、Cost 与 Production Support。

Management takeaways

本次 Update 希望达成的共识

Landscape 已基本看清 现有路径来自不同约束，当前能力定位和关系已形成初步共识。
方案互补，不是竞争 AMH、HASE 与 System Intelligence 分别验证不同价值。
不做过早技术合并 优先统一公共基础能力，保留 Provider 和体验的灵活性。
覆盖完整 SDLC Planning 到 Maintenance，旧系统和新系统都需要同一管理闭环。
Production Access 是关键依赖 需要生产账号、模型、Quota、文档能力及相应审批与支持。
Owner 与运行责任要同步明确 技术准入、业务价值、成本和 Production Support 必须形成闭环。

现在不是选择最终技术方案，而是确认共同方向、生产化前提， 并授权一个有明确 Owner 与成功标准的下一阶段验证。

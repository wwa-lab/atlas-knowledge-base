根据当前选中的 3 个知识库，迁移可以分成 API 接入、幂等处理和 Legacy 兼容三部分。

1. 调用方需要完成的改造

  1. 新交易改用 POST /v2/points/adjustments，并使用公司 Workload Identity 获取短期 OIDC Token；旧的静态 Client Secret 不再接受。
  2. 每次请求必须携带稳定的 Idempotency-Key。重试时复用同一个 Key，避免 MQ Bridge 与 Event Gateway 双写期间重复记账。
  3. 消费方需要接受异步状态：初始返回 202 Accepted，最终结果由 points.adjustment.completed 事件确认；同步成功响应不能再作为记账完成依据。

2. AS400 兼容约束

Legacy AS400 批处理在 MVP 迁移期继续通过 MQ Bridge 接入。固定长度字段和 EBCDIC 编码保持不变，由 Bridge 负责映射到新事件格式；调用方不要直接修改 AS400 Copybook。每日 02:00–02:30 的结算窗口内只允许查询，不接受积分调整。

来源存在发布窗口冲突，Atlas 未自动裁决 Integration Standards 要求至少 14 天双写；AS400 Runbook 对低流量批任务写的是 7 天。请由 Reward Plus Owner 与 AS400 Owner 确认本次迁移窗口。

建议顺序：先完成 OIDC 与幂等改造，在预生产验证事件回调，再启用双写观察，最后由两个 Owner 共同确认切流。当前证据没有给出本次上线的最终日期。
